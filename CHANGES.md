# hls4ml + 4:2-Compressor-Based + Random-LSB Approximate Multipliers

This branch of `hls4mlrcoem` adds three new approximate-multiplier techniques
plus a plug-and-play optimization driver with last-layer-only targeting.

## What's new

### 1. 4:2-Compressor-Based Approximate Multiplier (`comp42_k4` / `comp42_k8`)

Implements the textbook 4:2 compressor (two chained full adders, with a
non-rippling lateral carry chain) and uses it as a building block for a
partial-product-reduction multiplier. Used as the `lo*lo` quadrant of an
LPOR-style split.

Files touched:
- `hls4ml/templates/vivado/nnet_utils/nnet_mult.h` -- new `compressor::`
  namespace with `comp42_exact_5to3`, `comp42_approx_5to3`,
  `comp42_counter_exact`, `comp42_counter_approx`, `comp42_reduce4`,
  `mult_comp42`; the `compressor_4_2_base<x_T, w_T, K>` class; aliases
  `comp42_k4` / `comp42_k8`.

### 2. Random-LSB Approximate Multiplier (`random_lsb_k4` / `random_lsb_k8`)

Replaces the `lo*lo` quadrant of an LPOR-style split with a *pseudo-random
bit pattern* generated by a 16-bit LFSR seeded with a compile-time `SEED`.
**No arithmetic is performed on the LSBs** -- the random pattern is a
constant at synthesis time, so the entire `lo*lo` multiplier collapses to
wires tied to VCC/GND, saving LUTs.

Files touched:
- `hls4ml/templates/vivado/nnet_utils/nnet_mult.h` -- new `random_lsb::`
  namespace with the `pattern<SEED, K>()` LFSR; the
  `random_lsb_base<x_T, w_T, K, SEED>` class; aliases `random_lsb_k4`
  (seed 0x1234) and `random_lsb_k8` (seed 0x5678).

### 3. `mult_strategy` extended to Conv1D / Conv2D layers

Previously only `Dense` layers exposed the `mult_strategy` ChoiceAttribute,
so the approximate multipliers could only be applied to fully-connected
layers. A CNN's last layer may be a Conv layer (fully-convolutional
network), so we now expose `mult_strategy` on `Conv1D` and `Conv2D` as well
(and update all six conv template locations to honor it).

Files touched:
- `hls4ml/backends/fpga/fpga_backend.py` -- the `mult_strategy` ChoiceAttribute
  is now shared across `Dense`, `Conv1D`, and `Conv2D` layers (with the
  same 8 choices: `standard`, `lpor_k4`, `lpor_k8`, `lsb_zero_k4`,
  `comp42_k4`, `comp42_k8`, `random_lsb_k4`, `random_lsb_k8`).
- `hls4ml/backends/vivado/passes/convolution_templates.py` -- all six
  config-template locations now honor `mult_strategy` (Conv1D, Conv2D,
  SeparableConv1D depthwise+pointwise, SeparableConv2D depthwise+pointwise)
  using the same pattern that `core_templates.py` already uses for Dense.

### 4. Plug-and-play optimization driver (`scripts/optimize_hls4ml.py`)

A YAML-driven pipeline. Each stage picks a *targeting mode*:

| `target:` value       | Meaning                                                       |
| --------------------- | ------------------------------------------------------------- |
| `all` (default)       | Every layer in the graph                                      |
| `last_layer`          | The last multiply-having layer only (skips Input/Flatten/etc.) |
| `last_layer` + `layer_type: Dense` | The last layer of a specific type (e.g. last Dense) |
| `by_name` + `names: [...]` | The layers whose `.name` matches                            |
| `layers: [Dense, Conv1D]` | (legacy) every layer of the given type                     |

Stages:

| Stage name           | What it does                                                |
| -------------------- | ----------------------------------------------------------- |
| `set_mult_strategy`  | Set `mult_strategy` on the target layer(s)                  |
| `set_random_lsb`     | Convenience wrapper that picks `random_lsb_k4` / `random_lsb_k8`; has an explicit `enabled: true/false` switch |
| `set_reuse_factor`   | Set the reuse factor                                        |
| `set_strategy`       | Set the implementation strategy (Latency/Resource/...)      |
| `set_precision`      | Set per-kind precision (io/weight/bias/accum)               |
| `set_attr`           | Generic fallthrough -- set any attribute                    |

After all stages run, the script re-applies the backend's
`vivado:apply_templates` flow so the generated `parameters.h` reflects
the new attributes (verified end-to-end: 8 sweep variants each produce
the correct `using product = nnet::product::<strategy><x_T, y_T>;` line
on the last Dense layer).

## Sample YAML

```yaml
pipeline:
  # Apply an approximate multiplier ONLY to the last Dense layer of the CNN
  - name: set_mult_strategy
    target: last_layer
    layer_type: Dense           # classifier head
    config:
      mult_strategy: comp42_k4  # standard | lpor_k4 | lpor_k8 | lsb_zero_k4 |
                                # comp42_k4 | comp42_k8 | random_lsb_k4 | random_lsb_k8

  # Turn on the random-LSB technique on the same last layer (flip `enabled` to toggle)
  - name: set_random_lsb
    target: last_layer
    layer_type: Dense
    config:
      enabled: true             # <-- on/off switch
      k: 4                      # 4 or 8
```

## Verification

Three Python reference scripts (under `scripts/`) simulate the bit-level
math without needing Vivado HLS:

    python scripts/verify_lpor.py        # the existing LPOR multiplier
    python scripts/verify_comp42.py      # the new 4:2-compressor multiplier
    python scripts/verify_random_lsb.py  # the new random-LSB multiplier

They confirm:
* LPOR is bit-faithful to its math claim; error matches `(2^K-1)(2^K-2)`.
* The 4:2 compressor conserves weight on all 32 input combinations; the
  multi-bit compressor tree produces a bounded error of `O(2^(2K))` for
  the approximate variant.
* The random-LSB multiplier's error is bounded by the max value of the
  lo*lo quadrant (`< 2^(2K)`); different SEEDs give different patterns.

## Caveats

* The new strategies only apply to `Dense`, `Conv1D`, and `Conv2D` layers.
  `DepthwiseConv1D`/`DepthwiseConv2D` reuse the conv templates so they
  also pick up the strategy; `SeparableConv1D`/`SeparableConv2D` have
  two internal sub-multiplies (depthwise + pointwise) and both honor
  `mult_strategy` independently.
* `mult_comp42<K, APPROX>` only supports K=4 and K=8 (1 and 2 compression
  levels). For other K it falls back to an exact integer multiply.
* `random_lsb_k4` uses seed `0x1234`, `random_lsb_k8` uses seed `0x5678`.
  To use a different seed, edit the seed in `random_lsb_k4` / `random_lsb_k8`
  in `nnet_mult.h` or add a new alias.
* Vivado/Vitis HLS itself is not installed in the test environment; the
  pipeline script generates the HLS C++ project and (if synthesis is
  enabled) calls `hls_model.build()`, which the user can run when they
  have Vivado/Vitis available locally.

## Quick start after extracting

```bash
cd hls4mlrcoem
pip install -e .                          # install the modified hls4ml
python scripts/verify_lpor.py            # confirm LPOR math is correct
python scripts/verify_comp42.py          # confirm 4:2-compressor math is correct
python scripts/verify_random_lsb.py      # confirm random-LSB math is correct
python scripts/optimize_hls4ml.py --config scripts/pipeline.yaml      # last-layer-only + random_lsb
python scripts/optimize_hls4ml.py --sweep    scripts/sweep.yaml         # benchmark all 8 strategies on last layer
```

To swap multiplier strategies, edit the `mult_strategy:` line in
`scripts/pipeline.yaml` and re-run. To turn the random-LSB technique on/off,
flip `enabled:` in the `set_random_lsb` stage.
